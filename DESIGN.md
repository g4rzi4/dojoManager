# Design System: DojoManager

## Overview

**Creative North Star: "The Color-Coded Dojo"**

Every area of the school owns one hue, carried by a tinted icon tile wherever that area appears: the sidebar, the page heading, the shortcuts. People find their place by color first and read second. The rest of the interface stays quiet so those hues can do that work: near-white ground, white surfaces, neutral text, one violet for action.

The surfaces are very round, hairline-bordered and softly lifted, floating over a faint dot grid. The density suits daily administrative work on a computer and a family checking a balance on a phone, and both get the same care. The system rejects the grey admin template with a single blue accent.

**Key Characteristics:**
- One hue per module, identical on every screen.
- Light only: near-white dotted ground, white surfaces.
- One family, Mona Sans, with bold headings and no tracked or uppercase labels.
- Very round corners, hairline borders, soft shadows.
- Violet is the action color and the focus color.

## Colors

A lavender-tinted light field where saturated color appears only as a module identity, a literal meaning, or an action.

The brand palette is five colors: `#F8F7FD` (ground), `#ECE9FA` (soft tint), `#5B3DF5` (primary), `#FF9F1C` (accent) and `#17123A` (ink). They live in `frontend/src/index.css`, which redefines Tailwind's `neutral` and `violet` scales from them, so screens keep using `neutral-*` and `violet-*` classes. In the dark view the roles swap: `#17123A` is the ground and `#F8F7FD` / `#ECE9FA` are the text.

### Primary
- **Dojo Violet** (`primary`, `#5B3DF5`): the primary action fill, focus rings, the input caret, the selected calendar day. It is also the Inicio module's hue. Hover deepens to `primary-deep`. `primary-tint` and `primary-ink` color the user avatar; `selection` and `selection-ink` color selected text.

### Accent
- **Belt Orange** (`accent`, `#FF9F1C`): the belt in the brand mark and favicon, with `accent-soft` for the knot. Use it sparingly, for brand moments only; it is not an action color and does not replace the amber of pending payments.

### Secondary
The module hues. Each has a `wash` (tile fill), `edge` (tile border), `ink` (icon) and `glow` (tile shadow).
- **Violet** (`inicio-*`): Inicio.
- **Sky** (`profesores-*`): Profesores.
- **Emerald** (`alumnos-*`): Alumnos.
- **Rose** (`eventos-*`): Eventos.
- **Orange** (`horario-*`): Horario.
- **Amber** (`pagos-*`): Pagos.
- **Teal**: Uniformes y protecciones.
- **Fuchsia** (`notificaciones-*`): Notificaciones.
- **Lime** (`tarjeta-*`): Mi tarjeta.

### Tertiary
- **Event types** reuse the module hues, as a wash and edge with a darker `chip-*-ink` and a solid `dot-*`: Clase orange, Examen de cinta emerald, Torneo rose, Cobro de mensualidad amber.
- **Payment status** chips: Pagado emerald, Pendiente amber, Vencido red (`danger-wash`, `danger-edge`, `danger-ink`).
- **Errors and destructive hover** use `danger-text`; the unread count uses `danger-badge`.

### Neutral
- The neutral scale is tinted with `ink` (`#17123A`), never pure gray.
- **Dotted Ground** (`ground`): the page, overlaid with a 22px grid of 1px dots at 7% ink.
- **White Surface** (`surface`): cards, sidebar, top bar, inputs.
- **Soft Fill** (`hover-fill`): hover and active rows, inactive chips, empty-state icon wells.
- **Hairline** (`hairline`, at 80% opacity on surfaces) and **Control Border** (`control-border`) for inputs, secondary buttons and neutral chips.
- **Text** from strongest to lightest: `text-title`, `text-heading`, `text-strong`, `text-body`, `text-placeholder`. `text-body` is the page default.

### Named Rules
**The Module Map Rule.** A module's hue means that module and appears the same in the sidebar, the page heading and its shortcuts. A new module gets its own unused hue. A new event type reuses the hue of the module it belongs to.

**The Literal Meaning Rule.** Colors that already mean something outside the app stay literal. A belt badge uses the belt's real color (`BELT_STYLES` in `types/student.ts`) and a class discipline uses its own color (`DISCIPLINE_STYLES` in `types/dojoClass.ts`), even where that hue matches a module.

**The Violet Action Rule.** The primary action on any surface is filled violet. Module hues identify; they do not ask to be clicked.

**The Light Only Rule.** The system is light only (`color-scheme: light`). No dark theme exists, so none of these tokens has a dark counterpart.

## Typography

**Display Font:** Mona Sans Variable (with ui-sans-serif, system-ui)
**Body Font:** Mona Sans Variable

**Character:** One grotesque carries everything, with hierarchy built from weight and ink rather than a second face.

### Hierarchy
- **Display** (700, 2.25rem rising to 3.75rem, 1.08): the login headline only.
- **Headline** (700, 1.875rem rising to 2.5rem at 640px, 1.25): every screen's page title, in `text-heading`, beside its large module tile.
- **Metric** (700, 1.75rem, 1.25): the figure in a shortcut card. Turns amber when something is owed.
- **Title** (700, 1rem, 1.5): section and card titles, in `text-title`.
- **Body** (400, 1rem, 1.5): page descriptions, capped near 42rem, and running text.
- **Body Small** (400, 0.875rem, 1.43): the most used size, for secondary lines, table cells and hints.
- **Label** (500 to 600, 0.875rem, 1.43): field labels and button text.
- **Chip** (600, 0.75rem, 1.33): badges and status chips.

### Named Rules
**The Plain Zero Rule.** Never set tabular figures on Mona Sans. Its tabular zero is slashed, verified in a render, and that hurts the legibility of money.

**The Quiet Label Rule.** Labels are sentence case at the default letter-spacing. Hierarchy comes from weight and ink.

## Layout

An app shell with a floating sidebar (288px) inset 12px from the viewport and a floating top bar, over content capped at 72rem. Below 1024px the sidebar becomes a slide-in drawer over a dimmed page, and the top bar gains the menu button and brand.

Each screen opens with its page heading: large module tile, title, description, then the work area. Login is one large rounded container with the headline and tilted, labelled module tiles on the left and the form in an inner panel on the right; on phones the tiles are hidden so the form stays near the top.

Spacing follows a 4px rhythm: 8 to 12px inside groups, 16 to 24px between blocks and as card padding, 32px at the most generous. Icon-only controls and compact buttons hold a 44px minimum target.

## Elevation & Depth

A hybrid of hairline borders and soft shadows whose wide blur and negative spread read as gentle lift. Tiles carry a small shadow tinted with their own module's `glow`. Depth is never structural on its own; every lifted surface also has a border.

### Shadow Vocabulary
- **Surface** (`box-shadow: 0 1px 2px rgb(23 23 23 / 0.04), 0 14px 32px -18px rgb(23 23 23 / 0.14)`): cards and the top bar.
- **Float** (`box-shadow: 0 1px 2px rgb(23 23 23 / 0.05), 0 18px 40px -20px rgb(23 23 23 / 0.2)`): the sidebar and the login container.
- **Tile** (`box-shadow: 0 6px 14px -8px <module glow>`): module tiles.
- **Primary Edge** (`box-shadow: inset 0 0 0 1px rgb(255 255 255 / 0.12), inset 0 1.5px 0 rgb(255 255 255 / 0.3), 0 8px 18px -10px rgb(91 61 245 / 0.75)`): every violet-filled button or link, replaced by the focus ring when focused.

### Named Rules
**The Soft Offset Rule.** Shadows are blurred and drawn in below the element. Hard-edged offset shadows do not belong here.

## Shapes

Everything is very round, and radius grows with the size of the thing: tiles and small controls, then panels and cards, then the sidebar, then the login container. Badges, chips and avatars are full pills or circles. Borders are 1px hairlines, except module tiles, which take a slightly firmer 1.5px edge.

### Named Rules
**The Nested Corner Rule.** An inner shape takes a smaller radius than its container, close to the outer radius minus the padding between them, as in sidebar links around their tiles and the top bar around its buttons.

## Components

### Buttons
Confident, filled and slightly pressable.
- **Shape:** large at 20px, compact at 16px.
- **Primary:** violet fill, semibold. The full-width form submit is 18px text; on-screen actions are the compact size at 14px with an optional leading icon.
- **Hover / Focus:** hover deepens the fill over 200ms; press scales to 0.98 on the large button; focus-visible shows a 2px violet ring offset by 2px. Disabled drops to 50% opacity.
- **Secondary:** white with a control border and strong text; hover fills with the ground color.
- **Icon-only:** 44px square, no fill at rest, soft fill on hover; destructive ones hover to danger red.

### Chips
- **Style:** full pill, 1px border, chip type. Event and status chips are wash, edge and dark ink; belts use their literal colors; neutral chips use soft fill and control border.
- **State:** informational only.

### Cards / Containers
- **Corner Style:** 28px.
- **Background:** white.
- **Shadow Strategy:** Surface.
- **Border:** 1px hairline at 80%.
- **Internal Padding:** 20 to 24px, up to 32px on larger panels.

### Inputs / Fields
- **Style:** white, 1px control border, 16px radius, with a medium-weight label stacked 8px above.
- **Focus:** border turns violet with a 4px pale violet ring.
- **Error:** an inline message in `danger-text`, announced as an alert.

### Navigation
- **Sidebar:** a floating white panel with the brand on top, the module list, and the user card and sign-out at the bottom.
- **Links:** small module tile plus label. Inactive tiles sit at 55% opacity and return to full on hover; the active tile is full strength on a soft-filled row with bold text.
- **Top bar:** a floating pill at the right holding notifications, spanning the width on phones.

### Module Tile
The signature element, decorative and paired with text. Wash fill, 1.5px edge, ink icon at 2.1 stroke (lucide), tinted shadow. Small in navigation, large in page headings and shortcut cards.

### Shortcut Card
A card that links to a module: large tile, label, metric, hint. Lifts 2px on hover.

### Brand Mark
A violet (`#5B3DF5`) rounded square holding a belt knot in the accent orange (`#FF9F1C`). The orange is the belt and does not represent Pagos.

## Do's and Don'ts

### Do:
- **Do** carry a module's hue through `ModuleTile` wherever that module appears.
- **Do** mute inactive sidebar tiles and keep only the active one at full strength.
- **Do** keep money amounts in proportional Mona Sans figures, with status spelled out in words.
- **Do** pair every status color with its label, and keep chip text at the `chip-*-ink` depth for 4.5:1 contrast.
- **Do** wrap every transition with a reduced-motion opt-out.

### Don't:
- **Don't** use tabular figures with Mona Sans.
- **Don't** assign a module's hue to a different module or swap it per screen.
- **Don't** recolor belts or class disciplines to fit the module palette.
- **Don't** add dark-theme tokens without an approved system change.
- **Don't** use flashka.ai's logo, name, mascot or illustrations. It is a visual reference only.
- **Don't** tilt module tiles outside the login.
